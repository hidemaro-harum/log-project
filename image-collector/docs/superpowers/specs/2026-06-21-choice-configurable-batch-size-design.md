# Choiceバッチサイズ設定化

## 目的

Choice画像配置の容量上限をコード固定の80MBから`setting`シートで変更可能にし、初期値を70MBとする。未使用の楽天バッチサイズ設定は廃止する。

## 設定

- `setting`シートへ`Choiceバッチサイズ(MB)`を追加する。
- 初期値は`70`とする。
- 設定可能範囲は1MB以上80MB以下とする。
- 空欄、数値以外、範囲外の場合は、Drive操作やバッチシート生成を始める前にエラーで停止する。
- `楽天画像バッチサイズ(MB)`は設定定義から削除する。
- 「初期設定（差分更新）」実行時、既存の`楽天画像バッチサイズ(MB)`行だけを削除する。他の設定値と行は保持する。

## Choice配置

- Choice配置のドライランと本実行は、同じ`Choiceバッチサイズ(MB)`を使用する。
- バッチ分割関数へ容量上限を明示的に渡し、商品単位で分割する既存仕様を維持する。
- 1商品だけで設定上限を超える場合は、その商品を単独バッチにする既存仕様を維持する。
- バッチフォルダ名`batch_001`およびバッチTSV名`tsv_b1_XX品`の命名規則は変更しない。
- タイムアウト時の進捗保存と自動再開仕様は変更しない。

## 表示

- Choice配置ダイアログの説明、処理内容、注記には実際の設定値を表示する。
- ヘルプとREADMEの80MB固定表記を、設定値に基づく説明へ変更する。
- `Choice出力先フォルダURL`の説明から80MB固定表記を除く。

## やり直し手順

1. Choice配置処理が実行中・再開待ちでないことを確認する。
2. Choice出力先フォルダ内の既存`batch_...`フォルダを削除する。
3. スプレッドシート内の既存`tsv_b...`シートを削除する。
4. 統合先フォルダの元画像は削除しない。
5. 「初期設定（差分更新）」を実行し、`Choiceバッチサイズ(MB)`が`70`であることを確認する。
6. Choiceドライランでバッチ数と容量を確認する。
7. Choice配置実行を開始する。

## テスト

- 70MBを境界に商品単位でバッチが分割されること。
- 設定値を変更すると分割結果が変わること。
- 空欄、数値以外、0以下、80超過を拒否すること。
- 差分更新で楽天バッチサイズ行だけが削除され、既存設定値が保持されること。
- ダイアログに実際のChoiceバッチサイズが表示されること。
- 既存のChoice画像配置、TSV生成、タイムアウト再開テストが通ること。
