# 楽天CSVから対照表を自動補完する設計

## 目的

`number_mapping`への手入力を減らすため、`rakuten_csv`を正として`商品管理番号（商品URL）`と`SKU区分`を自動補完する。番号変換の安全確認に必要な商品グループキーは維持する。

## 入力と照合

- `number_mapping`の`旧システム連携用SKU番号`を照合キーとする。
- `rakuten_csv`では、`SKU管理番号`があり`選択肢タイプ`が空の行をSKU行として扱う。
- SKU行の`システム連携用SKU番号`が旧番号と一致する行を検索する。
- 一致したSKU行の`商品管理番号（商品URL）`を対照表へ補完する。
- 同じ商品管理番号を持つSKU行数が1件なら`シングル`、2件以上なら`マルチ`を補完する。
- 前後空白を除去し、英字の大文字小文字を区別せず照合する。シートへ書く値は楽天CSVの表記を維持する。

## 更新ルール

- メニュー`🔄 番号移行`へ`① 楽天CSVから対照表を補完`を追加し、既存項目の番号を繰り下げる。
- 更新対象は`商品管理番号（商品URL）`と`SKU区分`の2列だけとする。
- 対象セルが空欄の場合だけ補完する。
- 既存値が判定結果と一致する場合は変更せず、補完済みとして数える。
- 既存値が判定結果と異なる場合は上書きせずエラーにする。
- 一致するSKUがない、同じ旧SKU番号が楽天CSV内で複数商品に一致する、商品管理番号が空欄の場合はエラーにする。
- エラーが1件でもある場合は一切書き込まない。利用者が内容を修正して再実行する。
- 同じデータで再実行しても追加変更が発生しない冪等な処理とする。

## 実行結果

- 実行前に変更予定、補完済み、エラー件数を計画する。
- エラー0件の場合だけ2列を列単位で一括書き込みする。
- 完了ダイアログに補完件数と補完済み件数を表示する。
- エラー時は行番号と理由を表示し、`検証結果`列にも対象行の理由を記録する。
- 実行結果は既存の`execution_history`へ記録する。自動補完は復元可能な派生値だけを扱うため、バックアップシートは作成しない。

## 既存処理との関係

1. 利用者は旧・新商品番号と旧・新システム連携用SKU番号を入力する。
2. `楽天CSVから対照表を補完`を実行する。
3. `対照表を検証`を実行する。
4. 楽天・ANAのドライランと本実行を行う。

既存の番号移行処理では、補完後の`商品管理番号（商品URL）`と`SKU区分`を従来どおり必須として扱う。

## テスト

- シングルSKUのURLと区分を補完する。
- マルチSKUの各対照表行へ同じURLと`マルチ`を補完する。
- 入力済みの一致値を変更しない。
- 入力済みの不一致値を上書きせずエラーにする。
- 未一致SKU、重複SKU、商品管理番号空欄をエラーにする。
- エラーがある場合に部分書き込みしない。
- 商品番号、旧・新SKU番号、備考など対象外列を変更しない。
- 全既存テストと全JavaScript構文確認を通す。

## デプロイ

Sadoの`.clasp.json`と追跡対象を確認し、全検証後に`clasp push`する。
