# 佐渡市 画像集約・ポータル配置ツール (image-collector)

Google Driveに分散した返礼品画像を集約し、Choice、ANA、楽天向けの画像配置とCSV/TSV作成を補助するGoogle Apps Scriptツール。

## 初期設定

1. 対象スプレッドシートを開く。
2. メニュー「📷 画像集約」→「⚙️ 初期設定（差分更新）」を実行する。
3. `setting` シートに、統合先フォルダURLと利用するポータルの設定値を入力する。

既存のスプレッドシートでは、コード更新後に初期設定（差分更新）が必要になる場合がある。`rakuten_dashboard` などの不足シートもこの処理で作成される。設定を消して作り直す「初期設定（新規再生成）」は、入力済みの設定値を削除するため注意すること。

空のまま残った、または標準ヘッダーの先頭部分だけが書き込まれたポータル用シートは、差分更新時に安全に修復される。データや標準外ヘッダーがある既存シートは上書きしない。

## 画像集約

1. `master` シートに `管理番号` と `フォルダリンク` を貼り付ける。
2. 「📋 ドライラン（テスト）」で対象件数を確認する。
3. 「🔍 全行実行」で統合先フォルダへ画像をコピーする。
4. `dashboard` シートで進捗とエラーを確認する。

| 管理番号 | フォルダリンク |
|---|---|
| 001 | https://drive.google.com/drive/folders/xxx |
| 002 | https://drive.google.com/drive/folders/yyy |

- 元画像は削除せず、画像ファイルだけをコピーする。
- 統合先はフラットな構造とし、同名ファイルはスキップする。
- 27分で中断した処理はトリガーで自動再開する。

## 画像差分抽出

1. `setting` の `差分画像保存先フォルダURL` に新規画像の保存先を設定する。
2. `master` に第1弾・第2弾を含む画像フォルダを記載する。
3. 「🆕 画像差分抽出」→「📋 差分抽出 ドライラン」で予定件数を確認する。
4. 「🚀 差分抽出 実行」を開始し、`dashboard` と `execution_history` で結果を確認する。

- 統合先と差分保存先のどちらにも同名ファイルがない画像だけをコピーする。
- 同名判定はファイルの実名を小文字化して行い、大文字・小文字を区別しない。名前の前後の空白は除去しない。
- 内容だけが変わった同名画像は差分対象外となる。ファイル内容と更新日時は比較しない。
- 比較元の統合先、コピー元フォルダ、その中の元画像は変更・削除しない。コピー元の直下の `image/*` だけが対象。
- 再実行時は差分保存先の既存画像もスキップする。長時間処理は行境界で中断し、約1分後に自動再開する。
- 統合先・差分保存先・コピー元はDrive APIでページ単位に列挙する。大きな1フォルダの途中で時間制限に達しても、ページとページ内位置から自動再開する。
- dashboardの行詳細は件数と文字数を制限し、省略件数を表示する。
- 完了・異常終了は実行履歴に記録し、通知先メールアドレスがある場合は本実行の結果を通知する。

## Choice配置

- `choice_tsv` にChoiceから出力したTSVをヘッダー行ごと貼り付ける。
- `setting`の`Choiceバッチサイズ(MB)`に従って画像を分割し、バッチ別TSVを作成する。初期値は70MB、設定可能範囲は1〜80MB。
- 処理管理用の `出力バッチ` 列は既存列を再利用する。同じ処理を繰り返しても列を追加しない。
- `出力バッチ` は内部列であり、生成するTSVには含めない。
- 画像コピーが1枚でも失敗した商品はバッチTSVから除外し、元TSVの `出力バッチ` を `エラー` にする。
- `品梱包画像`は`{管理コード}_9.*`を優先する。`_9`がない場合は、統合先フォルダ直下の`Sado,_Niigata.jpg`を使用する。
- 共通の品梱包画像は各Choiceバッチフォルダへ1ファイルだけコピーし、同じバッチ内の商品から共有する。
- `_9`のない商品があるのに`Sado,_Niigata.jpg`が見つからない場合、ドライラン・本実行ともバッチ作成前に停止する。
- 予約・自動再開待ちの処理がある場合、新規実行は既存進捗を保護するため拒否される。

### Choice配置をやり直す場合

1. Choice配置が実行中・再開待ちでないことを確認する。
2. Choice出力先フォルダ内の`batch_...`フォルダを削除する。
3. スプレッドシート内の`tsv_b...`シートを削除する。
4. 統合先フォルダの元画像は削除しない。
5. 「初期設定（差分更新）」を実行し、Choiceバッチサイズを確認する。
6. Choiceドライラン、配置実行の順に実行する。

## ANA配置

- `ana_csv` の画像ファイル名を基にANA用フォルダへ画像を配置する。
- JPEG以外の画像は、拡張子だけでなく画像データもJPEGへ変換し、出力名を `.jpg` にする。
- WebPなどGASで直接変換できない形式や直接変換に失敗した画像は、Google Driveのサムネイルを使ってJPEG化する。サムネイル経由では解像度が変わる可能性があり、サムネイルを取得できないファイルは変換に失敗する。
- 処理管理用の `出力バッチ` は既存列を再利用し、ANA CSVには含めない。
- ANA CSVはブラウザ側でUTF-8 BOMを付けてダウンロードする。
- ANA画像配置は必須画像列の不足・重複をDrive操作前に検出する。
- 予約・自動再開待ちの処理がある場合、新規実行は拒否される。破棄してやり直す場合だけ「進捗リセット」を使用する。

## 番号移行（Choice・楽天・ANA）

初回は「⚙️ 初期設定（差分更新）」を実行し、`number_mapping`と`number_migration_dashboard`を作成する。`number_mapping`は1行1SKUで、次の列を入力する。

| 商品管理番号（商品URL） | 旧商品番号 | 新商品番号 | 旧システム連携用SKU番号 | 新システム連携用SKU番号 | SKU区分 | 備考 | 検証結果 |
|---|---|---|---|---|---|---|---|
| 楽天CSVから自動 | `old-item` | `new-item` | `old-sku` | `new-sku` | 楽天CSVから自動 | 任意 | GASが更新 |

- 利用者が入力するのは、旧・新商品番号と旧・新システム連携用SKU番号の4項目。
- `商品管理番号（商品URL）`と`SKU区分`は、旧システム連携用SKU番号を使って`rakuten_csv`から自動補完する。
- シングルSKUは、商品番号とシステム連携用SKU番号を旧・新それぞれ同じ値にする。
- マルチSKUは、同じ旧・新商品番号をSKU数分繰り返し、各SKUの新旧システム連携用SKU番号を入力する。
- マルチSKUの商品番号は、その商品のシステム連携用SKU番号の1つと同じでもよい。`① 楽天CSVから対照表を補完`は、楽天の商品番号と一致する旧SKUをアンカーにし、そのSKUの新番号を共通の新商品番号として全SKU行へ補正する。SKU番号自体は各行の値を維持する。
- 例えば楽天の商品番号が`AR001`、SKUが`AR001`〜`AR009`の場合、対照表には9SKUすべてを記載する。全行の旧商品番号は`AR001`、新商品番号は`AR001`の新システム連携用SKU番号に統一する。`AR002`〜`AR009`は商品番号ではなくSKU番号として扱う。
- `AQ009MP`のように楽天の商品番号がSKU一覧に存在しない場合は、マルチSKU専用の商品番号として扱う。いずれか1行に旧商品番号と新商品番号を入力すれば、①が同じ商品の全SKU行へ共通値を展開し、同名のSKUアンカー行は要求しない。
- ①は、対照表で対象になった商品の楽天SKUを全件突合する。不足SKUがある場合は同じ商品の既存行すべての`検証結果`へ不足一覧を一度で表示する。エラー行を削除して解消するのではなく、不足しているSKUの対照行を追加する。
- 番号は楽天仕様に合わせて32 UTF-8バイト以内。空欄、重複、異なる商品間の新番号衝突、マルチSKU件数不一致は本実行を停止する。
- `商品管理番号（商品URL）`と`SKU管理番号`は不変キーであり、GASは書き換えない。
- 楽天番号移行では`商品名`カラムは必須ではない。商品行は`商品番号`があり、`SKU管理番号`と`選択肢タイプ`が空の行として判定する。
- 自動補完は空欄だけを更新する。入力済みのURLまたはSKU区分が楽天CSVと異なる場合は上書きせず、`検証結果`にエラーを記録する。
- 旧システム連携用SKU番号が楽天CSVに存在せず、新旧の商品番号とSKU番号がそれぞれ一致する行はシングルSKUと判定する。`SKU区分`へ`シングル`、`備考`へ`[楽天CSV対象外]`を設定し、楽天番号移行だけをスキップする。ChoiceとANA用の新旧番号、および重複・文字数・番号整合性の検証は維持する。

実行順序:

1. `number_mapping`へ旧・新商品番号と旧・新システム連携用SKU番号を入力する。
2. 「① 楽天CSVから対照表を補完」を実行し、商品管理番号とSKU区分を自動入力する。
3. 「② 対照表を検証」を実行する。
4. ChoiceはJ列のXLOOKUP例を使い、旧管理コードを新システム連携用SKU番号へ変換する。GASは`choice_tsv`を自動上書きしない。
5. 「③ 楽天ドライラン」を実行し、`number_migration_dashboard`の差分とエラー0件を確認する。
6. 実行前に、元の`rakuten_csv`全体を別スプレッドシートなど同一ブック外へコピーして保管する。同一ブック内には完全コピーを作成しない。
7. 「④ 楽天変換実行」で、対照表に紐づく商品ブロックだけを新番号へ変換して`rakuten_csv`を直接再構築する。対象外の商品・先頭の孤立行・末尾の旧行は消去される。
8. 再構築後の`rakuten_csv`を目視確認し、「⑤ 楽天CSVをダウンロード」で楽天取込用の`normal-item.csv`をShift-JISで出力する。現在の対照表との不一致、未変換、対象外行、確認中の変更があれば出力を停止する。
9. 「⑥ ANAドライラン」後に「⑦ ANA備考反映実行」を実行する。`返礼品識別コード`は変更せず、新システム連携用SKU番号を`備考(内部用)`へ設定する。

③・④は`number_mapping`に記載された商品URLだけを検証・変換する。`rakuten_csv`に存在していても、対照表に記載のない商品・SKUは対象外として無視する。

本実行は、対照表と対象CSVがドライラン時と完全に同じ場合だけ可能。実行直前にスプレッドシートと同じDriveフォルダへ`rakuten_csv_backup_yyyyMMdd_HHmmss.csv`または`ana_csv_backup_yyyyMMdd_HHmmss.csv`を作成し、元行番号、商品URL、SKU管理番号、変更列、変更前後の値だけをコンパクトバックアップしてから更新・再検証する。バックアップは復元に必要な差分であり、元CSVの完全コピーではない。結果は`execution_history`に記録し、通知先メールアドレスがあれば本実行完了・異常終了を通知する。

## 楽天配置

### R-Cabinet画像取得

- 「楽天配置」→「② R-Cabinet 画像取得」は、R-CabinetフォルダIDをカンマ区切りまたは改行区切りで複数入力できる。
- 複数フォルダを指定した場合、各フォルダの画像一覧をまとめて `rakuten_image_list` に書き出す。
- 同名画像が複数フォルダに存在する場合、後続の画像パイプラインで誤反映しないよう画像取得を停止する。
- 取得後は通常通り「③ 画像パイプライン（一括）」を実行する。

### Drive画像の小文字化・最適化

1. 「初期設定（差分更新）」を実行する。
2. `setting`の`楽天画像変換元フォルダURL`と`楽天画像変換先フォルダURL`を入力する。同じフォルダは指定しない。
3. 「楽天画像変換 ドライラン」で出力名、変換予定、同名衝突、非対応形式を確認する。
4. 「楽天画像変換 実行」を開始し、`rakuten_image_convert_dashboard`で進捗と結果を確認する。

- 変換元フォルダ直下の画像だけを対象とし、元画像は変更・削除しない。
- JPEGの`.jpg`と`.jpeg`は拡張子を維持し、ファイル名と拡張子の英字を小文字化する。
- PNGとWebPはJPEGへ変換して`.jpg`で出力する。GIFなど非対応形式はエラーとしてスキップする。
- 2MB以上、または幅・高さのどちらかが3840px以上の画像は、縦横比を維持して最大辺3840px以下・2MB未満になるよう段階的に縮小する。
- 小文字化・JPEG変換後に同名となる画像、または変換先に同名画像がある場合は、その画像だけをスキップしてダッシュボードへ記録する。
- 本実行は25分で進捗を保存し、約1分後に自動再開する。

### FTP登録失敗画像の抽出コピー

1. 「初期設定（差分更新）」を実行し、`rakuten_failed_files` シートを作成する。
2. `rakuten_failed_files` のA列 `ファイル名` に、FTP登録で失敗した画像ファイル名を貼り付ける。
3. 「楽天配置」→「⑩ FTP失敗画像コピー」を実行する。
4. コピー元のGoogle DriveフォルダURLと、コピー先のGoogle DriveフォルダURLを入力する。

- コピー元フォルダ直下から、A列のファイル名と完全一致する画像だけをコピーする。大文字・小文字は区別しない。
- コピー先に同名ファイルが既にある場合はコピーせず、`コピー先に存在` として記録する。
- 結果は `rakuten_failed_files` の `ステータス`、`コピー先URL`、`備考` に書き戻す。
- コピー元とコピー先に同じフォルダは指定できない。

### HTMLテンプレート差込

- Choiceとの照合キーは `choice_tsv.管理コード = rakuten_csv.システム連携用SKU番号`。
- `rakuten_template` はA列がテンプレートキー、C列がテンプレート本文。キーは `TEMPLATE_PC_DESC`、`TEMPLATE_SP_DESC`、`TEMPLATE_PC_SALES` を使用する。
- `{{説明}}` のように、`choice_tsv` のヘッダー名をそのままプレースホルダーに指定できる。
- 仮想プレースホルダー `{{配送温度帯}}` は、Choiceの常温・冷蔵・冷凍フラグから生成する。
- 値が空、または該当ヘッダーがないプレースホルダーは `-` に置換し、`rakuten_dashboard` に警告を記録する。
- `{{（必須）お礼の品名}}` は半角 `|` または全角 `｜` 以降の補足を除去する。
- Choiceデータまたは新画像がない商品はHTML・既存画像を変更せず、理由を`rakuten_dashboard`へ記録する。
- 画像マッチングは楽天CSVの商品行の`商品番号`を優先する。商品番号に対応する画像がない場合だけ、先頭SKU行の`システム連携用SKU番号`で画像を探す。
- `rakuten_image_mapping`を使う場合は、`管理コード`に楽天CSVの商品番号またはシステム連携用SKU番号を入れ、`R-Cabinet商品番号`に画像側の商品番号を入れる。
- 更新対象では商品画像1〜20を一度すべてクリアし、新画像を先頭から最大20枚設定する。ALTは楽天の商品名を優先し、なければChoice品名を使う。
- 生成HTMLは先頭の空白・タブ・改行だけを除去する。3列のいずれかが50,000文字を超える商品は全体を変更しない。
- 本実行前に変更対象列をUTF-8 BOM付きCSVでスプレッドシートと同じDriveフォルダへバックアップする。失敗時は書込みを開始しない。
- 最大200商品ずつ一括更新し、約25分で中断した場合は約1分後に自動再開する。再開までに入力が変わった場合は停止する。
- 実行中または再開待ちに④を再実行した場合は、既存進捗を保護するため拒否する。

### CSV出力

- `rakuten_csv` から全行または選択行を出力する。
- 楽天CSVはブラウザで `encoding-japanese` を使ってShift-JISへ変換してダウンロードする。
- マルチSKUの各SKU行は、新システム連携用SKU番号の1枚目を`SKU画像パス`へ設定し、`SKU画像タイプ`を`CABINET`にする。新番号画像がない場合だけ旧番号画像を使い、警告を記録する。
- マルチSKU画像が1件でも見つからない場合、楽天CSV出力は停止する。シングルSKUのSKU画像列は更新しない。

## 注意事項

- Driveの共有設定によりアクセスできないフォルダはエラーとして記録される。
- 大量データでは複数回の自動再開が発生する可能性がある。
- 本実行前にドライランを行い、対象件数、ファイル数、出力先を確認する。
- 画像集約では同じフォルダリンクを複数行に記載しても、同一フォルダIDは1回だけ走査される。
- 予約・実行・再開待ちの画像集約がある場合、新規実行は既存進捗を保護するため拒否される。
- `execution_history`シートには、画像集約、Choice、ANA、楽天主要処理、CSV検証の結果が追記される。
- ANA・楽天CSVは必須ヘッダー、識別キー、明示的な処理エラーを検出すると出力を停止する。
- 楽天APIはHTTP 429または5xxに限り、待機時間を延ばしながら最大3回試行する。
