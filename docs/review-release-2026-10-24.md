# BiteLog コードレビュー・リリース記録（2026-10-24）

写真編集・並べ替え・店舗詳細からの写真追加を含む現在の作業ツリーをレビューし、保存の再試行とデータの整合性を改善した。既存の未コミット変更も保持し、`codex/mogureco-csv-import` ブランチの変更一式を今回のリリース対象とする。

単体テスト・lint・ブラウザー回帰検証・本番ビルド、本番RLS修正、GitHubへのpush、Vercel本番デプロイと公開後の確認まで完了した。

## レビューで修正した問題

| 問題 | 対応 |
| --- | --- |
| 店舗・訪問の保存や写真の追加で応答が途切れると、再送時に同じ記録を重複作成しうる。 | フォーム内で親レコード・写真のIDと保存済みの段階を保持し、同じID・保存パスで再試行する。写真の確定分は再送対象から外し、結果が不明な保存の後は入力・写真の編集を固定する。 |
| 保存開始直後の連打で、複数の保存処理が並行して進みうる。 | 同期的な処理中フラグで二重送信を防ぐ。 |
| 写真行の保存結果が不明なとき、後処理の `storage.remove` によって保存済み写真の実体を削除しうる。 | 写真保存失敗を理由とする安易な削除を取り除き、安定したIDでの再試行に寄せる。CSVインポートに残っていた同様の削除も除去する。 |
| 住所が未入力の同名店を、自動登録統合や重複整理で同一店舗と扱う。 | 住所がない場合はGoogle Place IDの一致を必要とし、ID不明の別支店を同じ整理対象へ混ぜない。 |
| 店名が一致すれば、異なる都道府県の候補でも位置・Place IDを自動適用できる。 | 既存の都道府県判定を使い、明確な都道府県不一致を低確度とする。短縮住所だけでなく完全な住所も使い、自動適用を止める。 |
| 写真のRLSで、訪問の所属店舗を確認する列参照がサブクエリ内の列へ解決され、同一店舗の検査になっていない。 | `photos.restaurant_id` と `photos.visit_id` を明示し、insert/updateの両方で店舗所有者・訪問所有者・訪問と写真の所属店舗を検査する。 |
| 店舗削除で写真ファイルを先に消すと、その後のDB削除失敗で写真のない店舗レコードが残る。 | DB削除の成功を確認してから写真ファイルを削除する。写真削除だけが失敗した場合は、同じ画面から再試行できる。 |

## 共通処理への整理

- `src/hooks/use-modal-dialog.ts`: 写真追加・編集・プレビューのモーダル処理を共通化。重なったダイアログのEsc、フォーカス復帰、背景スクロール制御をまとめる。
- `src/lib/form-save-session.ts`: フォームが使うID、成功した保存段階、実行中の同じ保存要求を保持する。失敗した段階は再試行できる。
- `src/lib/browser-photo-upload.ts`: WebP変換、Storageの同一パスへのupsert、写真行の同一IDへのupsertを共通化する。

## 継続課題

- `src/lib/restaurant-delete.ts`はDB削除の確認後にStorageを削除し、DB失敗・応答不明時に写真実体を失う問題を修正した。Storage削除に失敗した場合は同じ画面から再試行できるが、画面を離れると孤立したprivate objectが残りうる。永続的な回収ジョブは未実装。
- CSVインポートでは危険な`storage.remove`を除去した。インポート全体の途中失敗・再実行管理は今回の対象外。
- 写真保存の再試行情報は開いているフォーム内で保持する。フォームを閉じたりページを再読み込みした後の再開は対象外。
- 拡大プレビュー中の写真の前後移動、写真ごとの料理名・メモは引き続き改善候補。
